# WATANY PRODUCT UX CONSTITUTION
## Supreme UX Doctrine
## Version 1.0
## Status: FROZEN BASELINE

---

# 1. PURPOSE

Watany exists to serve retired military personnel and their families.

This product is NOT:

- a chatbot
- a document archive
- a government website
- a dashboard
- a desktop web app forced into mobile

Watany IS:

```text
mobile-first veteran services platform
+
AI assistant
+
community platform
+
guided action app
```

Every design decision must serve:

```text
speed
clarity
confidence
low digital literacy
elder usability
```

---

# 2. DESIGN PHILOSOPHY

Core rule:

```text
talk naturally
act simply
never get lost
always know the next step
```

---

# 3. EXPERIENCE MODES

Watany uses 3 operating modes.

---

## MODE A — CONVERSATION

Use when:

* chatting with assistant
* support
* community discussion
* session discussion

Feel:

```text
WhatsApp
```

Behavior:

* chat rows
* threads
* bubbles
* timestamps
* typing
* unread
* voice notes
* attachments
* quick CTA

---

## MODE B — SERVICE

Use when:

* salary
* procedures
* payments
* recruitment
* grants
* documents
* laws
* complaints
* health
* tracking

Feel:

```text
mobile service app
```

Behavior:

* launcher icons
* guided flows
* cards
* forms
* CTA bars
* progress

---

## MODE C — LOOKUP

Use when:

* phone numbers
* payment status
* legal lookup
* quick answer
* service status

Feel:

```text
instant utility
```

Behavior:

* inline answer
* call button
* share button
* follow-up CTA

# 12. ASSISTANT ROLE

Assistant helps users use Watany.

Assistant does NOT become the whole product.

Meaning:

wrong:

```text
everything in chat
```

correct:

```text
chat helps launch actions
```

---

# 13. ELDERLY RULE

Every screen must pass:

```text
Can a low-tech retired military user complete this alone?
```

If no:

redesign.

---

# 14. WHAT IS FORBIDDEN

Never reintroduce:

* sticky floating bars
* compressed desktop dashboards
* giant text service lists
* duplicate navigation
* 30-item scrolling walls
* assistant dominance
* tiny icon buttons
* hidden primary actions
* unclear exits
* feature disappearance

---

# 15. PRODUCT FEEL

Watany should feel like:

```text
WhatsApp
+
banking app
+
government services app
+
trusted veteran assistant
```

---

# 16. CHANGE CONTROL

UX changes require architecture review if they affect:

* navigation
* routing
* primary flows
* CTA doctrine
* accessibility rules
* community interaction model

---

# FINAL RULE

If a change makes the product harder for elderly veterans:

DO NOT SHIP IT.
